# 2차 리뉴얼 · 좌석 UI 인계

기준 시안 커밋은 `f79c0e9`이다. [리뉴얼 계획](pixel-art-renewal.md)과 [공용 치수표](renewal-slice-1-spec.md)를 따르며, [공용 배치](../public/renewal-layout.mjs)의 `buildSeatMapModel`에서 도면·좌석 상태를 읽는다. 개발 서버 또는 정적 서버에서 `/renewal-slice.html`로 열 수 있다.

## 구현과 통합 접점

- 매장 전체에서 1인룸·일반석, 입구·키오스크·통로를 표시한다. 구역 버튼은 같은 모델의 빈자리 수를 표시한다. 상세 도면에서는 책상, 의자, 좌석 방향과 상태를 실제 배치에서 투영한다. UI 기준 44×44 CSS px은 클릭 영역에만 적용했다.
- 좌석 키 `hall:0`, `hall:1`, `solo:0`을 그대로 사용한다. 화살표는 좌판 중심을 기준으로 초점을 옮기며 Enter는 선택한다. 하단에서 별도로 확정한다. Esc 또는 닫기로 빠져나오면 열었던 버튼이나 캔버스로 돌아간다.
- 예약 확인 중에는 중복 제출을 막고 상태를 알린다. 충돌 시 다른 좌석의 DOM을 유지한 채 점유 정보와 빈자리 수를 업데이트하고, 상세 구역과 좌석 초점을 남긴다.
- [좌석 선택 모듈](../public/renewal-seat-picker.mjs)은 `readModel()`과 비동기 `requestSeat(key)`를 받는다. 시안의 요청은 로컬 좌석 상태를 확인하고 기존 이동 함수를 호출한다. `?qa=1`에서 **다음 예약 충돌 재현**을 켠 뒤 확정하면 해당 좌석에서 충돌을 재현한다.
- 서비스 연결 시에는 운영 서버의 `reserve` 응답으로 좌석 상태를 먼저 동기화하고, 성공 뒤 이동을 시작한다. `409`는 `occupied`, 다른 실패는 `unavailable`로 전달한다. 서버의 내 좌석 키와 휴식 구역 상태를 사용하면 `readModel()`에 `mySeatAway`를 제공할 수 있다.

## 공용 기준 및 담당별 영향

- 공용 배치 모듈의 좌표, 좌석 키, 문·통로·가구 치수를 그대로 소비한다. 아트 `c40730d`와 이동 `ddd5259`의 `renewal-slice.js` 변경분을 좌석 UI와 순차로 3방향 병합해 파일 충돌이 없음을 확인했다.
- **공간·좌석 UI.** 시안의 도면 데이터는 일반석 두 자리와 1인룸 한 자리를 포함한다. 2·5·6인룸과 88석 배치를 확장할 때 룸별 열과 통로를 배치에서 받으며, 작은 화면의 밀집된 열에서 버튼 겹침을 다시 검수한다.
- **이동·서버 통합.** 현재 시안은 실제 예약 서비스와 별개로 동작한다. 운영 좌석도 치환, 실제 서버에 연결한 복수 브라우저 검수, 휴식 구역의 자리 비움과 복귀는 통합이 필요하다. 시안의 키오스크에서 개편된 흐름을 이용할 수 있다.

## 검증

- Chrome FHD 1920×1080에서 방향키로 입장하고 키오스크를 클릭했다. 도면의 입구 투영 좌표, Tab과 화살표 이동, Enter 선택, 별도 확정을 확인했다. `hall:1` 충돌 후 같은 일반석 열에서 `hall:0`이 유지되는 것을 확인하고, 재선택 후 착석·부팅·타이핑까지 진행했다. 내 자리 표시와 Esc 포커스 복귀를 확인했다.
- Chrome 320×568, 390×844, 568×320 모바일 에뮬레이션에서 일반석의 44×44 버튼 비겹침과 1인룸 터치 선택·확정·착석을 확인했다. 3840×2160에서도 1인룸 도면과 착석을 확인했다.
- 기존 예약 핸들러에 서로 다른 방문자 토큰으로 같은 `hall:0` 요청을 동시에 보내 한 요청이 `200`, 다른 요청이 `409`를 받는지 확인했다. 실패 응답에 해당 좌석의 점유 정보가 있었고 다른 방문자는 `hall:1`을 예약할 수 있었다.
- 단위 테스트 37개와 프로덕션 빌드를 통과했다.
