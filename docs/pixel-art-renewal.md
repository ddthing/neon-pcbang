# 길모퉁이PC방 2차 픽셀아트 리뉴얼 기획안

이 문서는 2차 리뉴얼의 공유 기준이다. 배치, 픽셀 아트, 이동, 좌석 선택, 환경 효과 작업은 이 문서의 순서와 검수 기준을 따른다. 진단 기준 버전은 운영에 배포된 커밋 `0b65f94`다. 아래 치수는 시안용이며, 제작 전에 확정해야 할 항목을 따로 표시했다.

## 1. 제품 목표와 변경 범위

- **웹게임으로 제공한다.** 가까운 시점 하나에서 캐릭터를 따라가고, 창 크기가 바뀌면 화면에 들어오는 공간을 조절한다. 플레이 중 전체 지도와 확대 모드를 전환하는 카메라 기능은 추가하지 않는다. 좌석을 고르는 도면은 키오스크와 좌석 메뉴 안에서 제공한다.
- **한 공간에서 사람이 쓰는 사물처럼 보이게 만든다.** 캐릭터, 문, 식물, 책상, PC를 같은 투영 방향과 픽셀 밀도로 제작한다. 몸의 어디가 좌판에 닿는지, 어디로 통과하는지, 손이 어떤 기기에 닿는지 실제 크기에서 읽혀야 한다.
- **매장 전체를 조립형 에셋으로 정리한다.** 바닥·벽은 타일, 가구는 개별 에셋, 동작과 가림이 필요한 부분은 레이어로 관리한다. 연관된 에셋은 전송용 시트로 묶을 수 있다.
- **기존 서비스와 연결한다.** 일반석 88개, 1·2·5·6인룸의 좌석 수와 기존 좌석 키를 유지하는 배치안을 우선 설계한다. 좌석 예약·자리 유지 외출·멀티플레이·매점 배달·채팅·미니게임 연결을 회귀 검수한다. 좌석 수·좌석 키·서비스 규칙을 변경해야 하면 변경 이유와 영향을 먼저 공유한다.
- **완료에는 웹 배포가 포함된다.** 전체 구역 검수를 통과한 커밋으로 운영 배포를 실행하고, 운영 게임 페이지와 해당 릴리스 에셋을 확인한다.

## 3. 공용 배치와 에셋 연결 규격

**한 벌의 배치 데이터가 렌더링, 충돌, 상호작용, 좌석도의 원본이 된다.** 현재 퍼센트 좌표와 서버 위치 표현은 이행 과정에서 어댑터로 맞출 수 있다. 새 배치의 에셋 앵커는 월드의 논리 픽셀 `(x, y)`로 정의하며 오른쪽이 `+x`, 아래쪽이 `+y`다. 기존 예약 식별자와 좌석 표시 번호는 좌표와 독립적으로 관리한다.

| 객체 | 함께 합의할 데이터 |
| --- | --- |
| 구역 | ID, 표시 이름, 외곽 벽·난간, 통행 바닥, 입장·복귀 지점, 도면에서 보일 구획 |
| 문과 출입구 | 출발·도착 구역, 문턱 중심, 문 앞 접근점, 반대편 정착점, 개방 방향, 열린 범위, 프레임 가림 |
| 가구 | ID, 기준점, 그림 영역, 발과 충돌하는 실제 바닥 점유 범위, 앞쪽 가림 레이어, 정렬용 깊이 |
| 좌석 | 기존 좌석 키, 표시 번호, 소속 줄·룸, 책상·의자 방향, 통로 접근점, 좌판 중심, 몸의 방향, 키보드 접점, 일어날 때 나오는 점 |
| 배달 | 고양이 출발점, 손님과 구분되는 작업 통로, 좌석 옆 정차점, 손 위치, 책상 위 쟁반 중심 |
| 파티클 | 발생 조건, 발생점·표시 범위, 가림 기준, 모션 감소 설정에서의 최종 표시 |

- 캐릭터의 이동·깊이 정렬 기준은 **발 위치**다. 머리·헤드셋은 충돌 폭에 포함하지 않는다. 착석 시에는 좌판 앵커와 자세에 맞춰 그린다.
- 좌석을 그릴 때는 바닥과 그림자, 책상과 의자의 뒤쪽, 앉은 캐릭터, 의자 등받이·가구 앞면, 플레이 안내 순으로 가림 관계를 맞춘다. 실제 가구와 동선의 깊이에 따라 가까운 쪽을 우선한다.
- 판정은 물리 점유 형태를 사용한다. 얇은 키보드나 수직 벽 그림자만큼 통행 면적을 잘라내지 않는다.
- 앵커와 치수의 이름, 호환할 좌석 키, 역할별 파일은 첫 시안에 함께 기록한다. 데이터가 합의되기 전에는 작업자가 자체 좌표표로 전체 구역을 따로 구현하지 않는다.
- **1차 시안 확정 기준 (후속 에이전트 공유 원본):** 데이터 모듈은 [`public/renewal-layout.mjs`](../public/renewal-layout.mjs) (`lib/renewal-layout.mjs`), 치수·변경 이유·검수 기록은 [`docs/renewal-slice-1-spec.md`](./renewal-slice-1-spec.md), 실행 가능한 시안은 [`public/renewal-slice.html`](../public/renewal-slice.html)에 정리했다.

> **[1차 시안 반영 요약 — 이유와 영향]** `640×360` 논리 월드(FHD `3×`, 4K `6×`), 캐릭터 `32px`(머리 `16px`, 발 충돌 `12×8px`), 문 `entrance 32×46px` / `solo-door 30×44px`, 메인 통로 `56px` / 좌석 통로 `36px`, 배달 쟁반 `14×10px`(정면)·`12×10px`(측면)을 확정했다. 1인석 책상 폭은 모니터(`26×19`)·본체·키보드·쟁반 동시 배치 및 팔꿈치 간섭 방지를 위해 시안치(`44–52px`) 대비 `56px`로 `+4px` 조정했으며, 1·2·5·6인룸 책상 시트·배달 앵커 규격에도 동일 기준을 적용한다. (상세 표: [`docs/renewal-slice-1-spec.md`](./renewal-slice-1-spec.md))

미술 방향은 첨부 레퍼런스에서 합의한 **남보라 그림자, 청회색 창틀과 바깥 풍경, 살구색 실내 조명, 원목·천·유리의 구분**을 따른다. 실내는 위에서 살짝 내려다보는 한 방향으로 통일하고, 입구와 테라스의 바깥 풍경에 깊이를 준다. 길모퉁이PC방의 오브젝트와 캐릭터는 자체 도안으로 제작한다.

바닥의 줄눈·목재 결은 낮은 대비로 몇 가지 변형을 만들고, 목재 상판에는 결, 타일에는 줄눈·반사, 벽에는 넓은 색 면을 쓴다. 강한 대비와 발광은 문턱, 모니터, 조명 주변처럼 조작과 공간 구조를 설명하는 곳에 집중한다. 치수는 **시안 캡처와 착석 영상 비교를 거쳐 확정**하며, 다른 구역에 적용하기 전에 기준을 문서에 기록한다.

## 5. 동선·카메라·모션

1. **수동 이동과 클릭 이동.** 키보드·터치·바닥 클릭은 같은 충돌 데이터를 사용한다. 클릭 목적지가 바닥이면 짧은 발밑 표시를 낸다. 벽이나 다른 구역을 클릭하면 그 위치에 도달 불가 피드백을 준다. 먼 통로로 임의 보정해 걷는 동작을 피한다.
2. **자동 착석과 이동.** 통로에서 의자 옆으로 접근하고, 발 방향을 바꾼 뒤 앉는다. 일어날 때는 먼저 통로 쪽으로 나온다. 같은 룸에서 자리를 바꾸면 해당 룸 통로를 사용한다. 멀티플레이에서 같은 자세·방향·좌석이 보이도록 상태를 연결한다.
3. **배달.** 고양이는 카운터 출구로 나와 통로를 따라간다. 좌석 옆에서 멈춘 뒤 쟁반을 내린다. 쟁반은 손 앵커에서 책상 앵커로 이어지고 주문 확정과 연동한다. 이용 중인 캐릭터나 등받이를 관통하는 장면을 검수한다.
4. **카메라.** 가까운 시점을 유지한다. 640×360 기준 시야와 FHD 3배·QHD 4배·4K 6배를 비교 기준으로 삼고, 임의 창 크기에서도 픽셀 선명도와 좌표 일치를 확인한다. 울트라와이드에서 여유가 생기면 좌우 공간을 더 보여준다. 모바일에서 채팅·조이스틱·하단 메뉴가 열린 상태를 별도로 시험한다.
5. **모션.** 걷기는 방향별 6프레임으로 시작하고, 발걸음을 이동 거리에 맞춘다. 착석·기립은 옆모습과 뒷모습 각각 4–6프레임 시안, 타이핑은 4프레임 시안으로 비교한다. PC 부팅은 LED → 부팅 화면 → 사용 화면 순서로 한 번 재생한다. 조리 → 담기 → 쟁반 들기 → 운반 → 내려놓기를 실제 소품과 맞춘다. 모션 감소 설정은 시간 지연이나 반복 효과를 줄이면서 상태 변화는 보여준다.

## 6. 좌석 선택 화면

기본 흐름은 **홀 전체 → 좌석 줄 또는 룸 → 자리 선택 → 하단 확정**이다. 전체 화면에는 구역, 문과 통로, 빈자리 수를 보여준다. 상세 화면에서는 책상 한 면과 의자 방향이 보이는 버튼을 사용한다. 6인룸은 실제와 동일하게 앞·뒤 3자리와 가운데 통로를 표시한다. 모바일은 고른 줄이나 룸을 펼쳐서 조작 영역을 **44×44 CSS 픽셀 이상** 확보하는 것을 목표로 한다.

| 상태 | 표시와 동작 |
| --- | --- |
| 이용 가능 | 빈 의자와 번호를 표시한다. |
| 선택 | 굵은 테두리와 체크 표시, 하단에 좌석 번호·룸 이름·이동 버튼을 표시한다. |
| 이용 중 | 손님 실루엣 또는 잠금 표시와 이용 중 문구를 함께 표시한다. |
| 내 자리 / 자리 비움 | 별과 내 자리 글자를 표시하고, 휴식 구역에 있으면 자리 비움 상태를 덧붙인다. |
| 예약 확인 중 | 확정 버튼에 처리 상태를 표시해 중복 제출을 막는다. |
| 예약 충돌 | 다른 손님이 먼저 잡은 좌석만 갱신한다. 보고 있던 줄·룸과 탐색 위치를 유지해서 다른 자리를 빠르게 고를 수 있게 한다. |

상태는 색과 함께 형태·문구로 표현한다. 키보드는 화살표로 자리 탐색, Enter로 선택, 별도 확정 버튼으로 예약할 수 있게 한다. 팝업을 닫으면 열었던 조작 버튼으로 포커스를 돌려준다. 좌석 번호·착석 위치·내 PC 표시·쟁반 위치는 같은 좌석 키로 확인한다.

## 7. 파티클과 정보 우선순위

| 효과 | 범위 | 검수 포인트 |
| --- | --- | --- |
| 비·눈·물튐 | 실내 비와 눈은 창 유리 영역, 물튐은 테라스의 노출 바닥 | 창틀·벽·카운터 뒤에 올바르게 가려진다. 발과 문턱 표시 위의 밀도를 낮춘다. |
| 조리·음식 증기 | 조리 중인 냄비 및 뜨거운 음식 위 | 조리 시작과 종료, 쟁반 착지에 맞춘다. 주문이 없는 동안 조리 증기가 반복되지 않는다. |

| 이동·착석 안내 | 클릭한 지점, 예약된 내 자리, 배달이 완료된 위치 | 먼지를 상시 붙이기보다 위치·상태를 짧게 보여준다. 모션 감소 설정에서도 정적인 표시를 유지한다. |

## 8. 작업 분담과 병렬 작업 순서

첫 작업은 **입구·키오스크·일반석 두 자리·1인석 한 자리**로 만든 실제 플레이 시안이다. 같은 캐릭터와 가구를 FHD와 4K에서 보고, 문 통과·착석·타이핑·일어나기·배달을 확인한 뒤 공용 비례와 좌표를 확정한다.

| 작업 | 맡을 범위 | 앞에서 결정할 것 | 다음 작업자에게 넘길 것 |
| --- | --- | --- | --- |
| A. 월드·공간 설계 | 통로, 구획, 문턱, 좌석·배달 앵커 | 첫 시안에서 가구 외곽과 유효 폭 합의 | 공용 배치 데이터, 시안 도면, 검수 동선 |
| B. 아트·캐릭터 | 바닥·가구·식물, 정면·측면, 착석·타이핑 프레임 | A의 기준점·픽셀 비례. 초기 스케치는 A와 병행 가능 | 소스 에셋, 사용할 프레임·가림 규칙, 실제 크기 캡처 |
| C. 이동·카메라·배달 | 충돌, 수동·자동 동선, 창 크기 변경, 배달 접점 | A의 통행 영역과 B의 발·손 기준점 | 경로 검수 결과, 실제 동작 영상, 남은 예외 |
| D. 좌석 선택 UI | 홀·룸 도면, 방향별 버튼, 모바일·키보드·예약 충돌 | A의 배치와 기존 좌석 키. UI 시안 및 상태 정의는 병행 가능 | 상태별 화면, 두 사용자 동시 예약 결과 |
| E. 조명·파티클 | 날씨, 증기, 반사, 이동 피드백 | A의 구역·유리·바닥 범위와 B의 가림 레이어 | 효과 켜짐·꺼짐과 낮·밤 비교 |
| F. 통합·배포 | 전 구역 검수, 회귀 검사, 운영 배포 | A–E의 통합 결과와 남은 문제 목록 | 배포 커밋·실행 링크·운영 검증 결과 |

작업을 시작할 때 기준 커밋과 이 파일을 함께 전달한다. 공용 좌표·치수·자산 방향이 바뀌면 이 문서의 시안 기준이나 배치 데이터를 먼저 갱신하고, 영향받는 작업을 기록한다. 각 작업 브랜치에는 담당 범위와 확인한 실행 경로를 남긴다. 예시의 숫자를 확정값으로 쓰거나 다른 작업자의 배치 구조를 복제하는 일을 피한다.
